# 发布前内容预审

这份预审用于把“内容准备好了吗”和“页面填好了吗”分开。它不是小红书官方规则库，也不承诺不违规、一定过审或一定获得流量；遇到当前平台细则时，以官方页面和用户实际账号提示为准。

## 1. 先固定事实边界

发布前建立一份简短的事实表：

| 项目 | 要确认的内容 |
|---|---|
| 目标 | 面向谁，解决什么问题，本篇主要任务是拉新、建立信任还是强化标签 |
| 承诺 | 标题、封面和正文共同承诺什么；三者必须一致 |
| 核心机制 | 本篇只保留一个主要方法、判断或故事，其余只能作为证据 |
| 证据 | 个人经历、数字、案例、政策、截图、引用的来源和授权状态 |
| 行动 | 用户看完要收藏、评论、站内私信，还是完成其他明确动作 |
| 视觉 | 封面精确标题、图片路径、图片文字、来源、版权和裁切安全边界 |

没有来源的数字、收益/效果、案例、身份、政策和时间敏感结论，先标为 `待核验`，不把它们写成已证实事实。

## 2. 内容质量检查

先诊断再改写，至少回答：

1. 解决谁的问题？
2. 用户为什么现在点进来？
3. 看完能带走什么？

继续检查：

- 第一屏/前 5 秒是否同时说明主题、继续看的理由和可信依据；
- 是否只有一个核心机制，正文是否压缩为一个方法、一个坑、一个对比或不超过三点；
- 是否有真实背景、具体场景、动作、前后差异或可核验材料；
- 标题是否能追溯到触发器（痛点、数字、对比、稀缺、共鸣、资源、反常识等），且没有把答案全部说完；
- 结尾是否给出真实的收藏、评论或站内互动理由，而不是泛泛的“欢迎交流”；
- 图文是否能拆成封面、问题、认知、方法/案例、操作、总结/互动等页面，每页只承载一个主要信息。

标题的 `≤20` 字是发布页面的硬校验；5-7 个话题、6-8 页图文、每周发布比例等只作可调整的起始建议，不能写成平台硬规则。

## 3. 两层风险预审

### 3.1 候选扫描

先扫描可能需要复核的入口：绝对化或保证性表述、收益/效果承诺、未核验数字和案例、站外联系方式或导流、虚构身份、未授权截图/图片、版权或商用关系、医疗/投资/金融/教育等高风险主题，以及标题—封面—正文不一致。

扫描命中只是候选，不等于违规；零命中也不等于安全。图片中的文字、截图、二维码、品牌标识和评论区行动引导也属于预审范围。

### 3.2 上下文复核

对每个候选判断：实际意图是什么、是否属于商业内容、主张有没有证据、证据是否授权、适用范围是否被夸大、是否与封面和正文一致、行动是否留在平台内。涉及高风险行业时，优先收窄断言并要求来源，不把经验当官方规则。

## 4. 保留原意的修复梯度

按影响最小的顺序处理：

1. 补充必要的商业关系披露或声明；
2. 补来源、原始数据、授权或案例边界；
3. 收窄绝对化、收益化和适用范围过大的断言；
4. 做最小改写，保留原钩子和账号口吻；
5. 仍无法支持时删除相关主张或暂缓发布。

不得使用谐音、拼音、拆字、表情、图片藏字等方式规避审核，也不要把“换个词”当成修复完成。修复后重新检查标题、正文、话题、封面文字、图片和行动引导。

## 5. 输出合同

预审结果必须输出以下之一：

- `可发`：未发现必须修改项，但仍需用户确认事实、账号和发布时间；
- `需修改`：列出“必须改 / 建议改 / 待确认”，给出具体替换文本和复检结果；
- `暂不建议发`：说明无法核验或风险过高的原因，以及需要补充的材料。

不要输出“绝对安全”“一定不违规”“保证不限流”等结论。

## 6. 批量内容与视觉交接

多篇任务额外记录：

- `input`：素材和已确认事实；
- `processing`：选题、初稿、视觉 brief；
- `inventory`：可直接发布的库存与预计可支撑天数；
- `output`：已排期内容与发布时间。

库存不足时先补库存、复用已验证主题或降低发布承诺，不为了日更硬凑低质量内容。阶段比例、两周缓冲和固定频率都只是实验假设，必须记录验证指标并在复盘时调整。

交给视觉流程时至少传递：封面精确标题、封面承诺、主体/来源、已确认事实、不可新增的数字、图片路径、输出比例和页面用途。没有真实调用图片工具或没有保存资产时，明确写 `imagegen: not_called`、`persistence: not_saved`，不得声称已生成或通过 QA。
